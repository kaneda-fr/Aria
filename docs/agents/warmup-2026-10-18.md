# Tool-capable startup warm-up — 2026-10-18

The maintainer resumed implementation on October 18, superseding the overnight stop,
then required Mac capture/playback to remain off. Eight headless Apollo comparison
cases completed. The Mac live client remains off.

The live adapter now primes the operational system prompt and tool schemas in a
direct one-token model call before lifespan readiness. It discards content and
proposed calls without dispatch, speech, admission, or conversation history.
The fixed readiness phrase is synthesized directly through Piper, avoiding a later
tool-free model request that could replace the warmed prefix. Warm-up failure prevents
readiness. Log-only tools, Mac playback, speaker attribution/confidence, and the
independent smoke/baseline profiles remain intact. No interruption work was added.

Files: [warm-up](../../scripts/e2e/live_warmup.py),
[server integration](../../scripts/e2e/live_server.py),
[Mac client](../../scripts/e2e/live_mac.py),
[comparison runner](../../scripts/e2e/warmup_compare.py).
GitNexus reported LOW impact for the Mac conversation entry (main caller), UNKNOWN
for dynamic server hooks; those callbacks were reviewed directly. Serena had no
language server, so fallback inspection/editing was used.

Validation: 24 targeted Apollo tests passed, covering discarded generated calls,
unchanged operational configuration/history, startup ordering, readiness speech
without model inference, shared request handling, log-only actions, confidence, and
exact logs. Syntax and context checks passed. Interactive Mac playback has not been
retested with the final implementation because the maintainer requested no Mac audio.

The comparison uses a fresh isolated Apollo/Ollama instance for every condition and
fixed French/English text through the shared worker. Default measurement is server
request start to generated audio ready. Mac playback is now explicit opt-in via
`--playback`; it is disabled in the resumed comparison. Both modes exclude microphone
capture, ASR, and endpointing. Two repetitions use alternating condition order.
`ARIA_E2E_WARMUP_TOOLS=0` is a comparison-only control; the interactive Mac client
requires tool-capable warm-up. Run without Mac audio:

```sh
.venv/bin/python scripts/e2e/warmup_compare.py --repeats 2
```

## Measured results

Run `20261017T222835Z-warmup-bb3ad9` completed all eight cases: two independent fresh
server/model runs per language per condition, with condition order reversed on the
second repetition. Same model, system prompt, tools, request, history, token budget,
speaker setting, and TTS path. No microphone or Mac playback. Metrics below are means
of two observations, not a general p95 or a voice end-to-end result.

| Language | Prior tool-free warm-up: request → audio ready | Tool-capable warm-up | Reduction | Prompt evaluation before → after |
| --- | ---: | ---: | ---: | ---: |
| French | 17.13 s | 6.39 s | 62.7% | 11.27 → 0.48 s |
| English | 16.55 s | 5.74 s | 65.3% | 11.22 → 0.44 s |

Warm-case request-to-audio ranges were 6.37–6.42 s FR and 5.72–5.76 s EN. Exact
reply strings matched within each language across all four runs, with 53 FR / 45 EN
generated tokens, one model call, and normal `stop` completion. No tested request
dispatched a tool. No warm-up admitted a user request, dispatched a tool, or added
history; first-request model history count was zero. Tools remained advertised and
the installed actions provider remained log-only. All eight network audits passed
with 11–13 loopback destinations each and no external/DNS attempts.

Startup warm-up now costs about 16.9 s instead of 6.8 s. Roughly ten seconds of
prompt work moved before readiness; it was not eliminated. Generation remains
about 4.66 s FR / 3.93 s EN, so this is a first-turn improvement, not completion of
the conversational-latency objective. The clock answers remain unhelpful because
the separate clock/router defect is unchanged. No command-selection improvement
is claimed. Cache counters were unavailable in this Ollama version; direct timings
and matched responses establish the measured effect without a cache-hit claim.

Warm-up runs at startup only. A later model unload or changed system/tool prefix can
make another request cold; idle retention and cache invalidation were not tested.
The runtime token budget stays 80; the one-token cap applies only to discarded warm-up.
All comparison services/tunnels were cleaned up. Apollo is started separately without
Mac capture/playback for readiness verification; log-only device actions remain.

Headless live run `20261017T223829Z-headless-live-788648` is ready on Apollo with
