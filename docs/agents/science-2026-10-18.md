# French science and model evaluation — Apollo, 2026-10-18

## Diagnosis and scope

The French sky/sunset errors reproduce with typed requests, independently of the
microphone and ASR. They are factual/model failures. The original 42-case suite
passed 40 cases but contained only four explanatory science turns. The expanded
`science_bench` reference passes **13/24**: 11/12 English and 2/12 French, counting
factual correctness, essential explanatory content and response language.
French failures include ice, seasons, sound in vacuum and rain; English also
incorrectly says two north magnetic poles attract. An accurate answer in the
wrong language fails. A correct direct yes/no answer need not add a mechanism
unless the question requests one. A keyword hit or empty automatic flags is not
evidence of factual correctness.

The reference uses the previous isolated Qwen2.5 3B run
`20261018T064141Z-prefill-logged-5fc113`. `science.json` contains the expanded
reference. A model download overlapped its early English cases, so those extended
timings are not a clean latency comparison; use the earlier uncontended 42-case
and queue reports instead. Private artifacts remain under the usual Mac
`~/Library/Logs/Aria/e2e/<run>/` and Apollo `/data/aria/e2e/reports/<run>/` directories.
No transcripts or real device names belong in shared documentation.

No science answer table, question regex, fact injected into a runtime prompt, or
cloud judge was introduced. Expected scientific principles live only in the
evaluation harness and are never sent to the model. Experiments compared local models/runtimes, prompt formatting, request-language
metadata and bounded cache preparation; rejected runtime changes were removed. The current action authorization policy is unchanged.

## Candidate selection and observed failures

- Three general-purpose prompt alternatives did not correct the French blue-sky
  error with Qwen2.5 3B; reject a prompt-only claim of success.
- Qwen3 1.7B Q4_K_M (Ollama metadata: 2.0B parameters, 1.36 GB) still gives wrong
  French science explanations. It is not an accepted replacement.
- Qwen3 4B Instruct 2507 improves sky/sunset but still gives false French seasons
  explanations and, under some prompts, wrong ice explanations. Its generation
  is slower on the Xeon. Concision must not remove the essential cause.
- Ministral 3 3B has stronger French results in the probes, but its stock template
  places the unchanged tool schema immediately before the **latest** user message.
  That shifts the prefix as history grows and costs roughly 10–12 seconds of
  prompt evaluation on sampled follow-ups. Some English inputs also receive
  French replies unless the request language is explicit.
- A strict 20-word style candidate omits preferential blue scattering or the
  longer atmospheric path in some answers. Those are incomplete explanations,
  even though the words are fluent and latency improves. Do not promote it on
  keyword-only checks.

The model families and tags were checked against the
[Ollama model library](https://ollama.com/library/ministral-3:3b-instruct-2512-q4_K_M)
and [Mistral's model documentation](https://docs.mistral.ai/models/ministral-3-3b-25-12).
Vendor capability claims do not substitute for these Apollo measurements.

## Retained changes and rejected experiment cleanup

The application request path, exact history and prefill have been restored to the
pre-experiment source. The opt-in language tag, predicted metadata prefill,
Ministral profile/template helper and strict 20-word prompt were removed after
observed regressions. They remain reproducible in private staged run archives.
No model default or action authorization change has been promoted.

The retained evaluation harnesses are `science_bench.py` (24 full-pipeline factual
turns with manual semantic review), `phrase_surface.py` (synthetic paraphrases),
and `model_tool_bench.py` (read-only real-model inventory queries). The isolated
launcher accepts explicit model, model-directory, prompt and local Ollama-binary
overrides. Cached assets are prepared before offline startup; overrides do not
download anything. The deployed server and global Ollama binary remain untouched.

The eight-token startup warm-up addresses a reproduced integration issue: on
Ollama 0.14.2 with Ministral, truncating “Aria is ready” at one token yields empty
content and a leading `A` on the next factual answer. Cold and warm probes both
reproduced this. Allowing the short warm-up to finish removed the defect. No
output, tool call or synthetic history is published. This is a bounded warm-up
workaround, not proof that every truncated generation is safe.

## Isolated newer runtime

Ollama 0.40.6 was prepared in a separate Apollo test directory, verified against
the official release checksum, and run in a loopback-only namespace. The deployed
0.14.2 binary/shared service was not replaced. See the
[official release](https://github.com/ollama/ollama/releases/tag/v0.40.6).
The 2B Qwen3.5 candidate still gives false French sky/seasons explanations and
makes an irrelevant device lookup for an English sunset follow-up. Its sampled
fresh requests rebuild roughly 6.6 seconds of prompt context despite common tool
schema, due to the recurrent checkpoint/cache behavior observed in runner logs.
It is rejected; smaller parameter count alone did not improve this workload.

Qwen3 4B Instruct on the new runtime, without a thinking override, correctly
answers the original sky/sunset questions in both languages. Its direct probe
still omits essential photosynthesis inputs in English and gives a misleading
French seasons explanation. A complete pipeline and queue comparison follows;
passing the original two questions does not establish general science accuracy.

## Validation status

No candidate meets the requested quality/latency no-regression condition.
The original French science defect is **not accepted as fixed**. Intermediate
runs are diagnostic evidence:

- `20261018T071630Z-science-stable-3e30d6`: correct French sky/sunset, but malformed
  first reply with one-token warm-up and about 0.35 s slower history follow-ups.
- `20261018T072701Z-science-final-3f1ff7`: complete startup warm-up removes the first
  reply defect; metadata prefill restores the French history follow-up to 2.21 s
  (previous baseline 2.24 s). The strict brevity prompt loses explanatory detail,
  and queued/English acknowledgment latency still regresses. This run is not
  accepted as the final fix despite its provisional directory label.

See the separate [interaction-surface audit](interaction-surface-2026-10-18.md)
for exact phrase gates, synonym failures, language heuristics and the missing wake
activation/conversation timeout. Deterministic controls passing does not establish
broad LLM interpretation or household interaction coverage.

### Full 4B/runtime comparison

Run `20261018T075110Z-qwen4-runtime-ebf06d` uses Qwen3 4B Instruct 2507 Q4_K_M
and isolated Ollama 0.40.6, original prompt, 12 history messages, 80 output tokens,
one worker and prefill enabled. The application Python SHA-256 map is identical
to the previous baseline. Startup warm-up uses eight discarded tokens. This
compares the model/runtime combination; it does not isolate either as the cause.

All 42 cases completed and automated flags were empty, but manual review scores
**40/42**: the French sky/sunset cases improve, while both French saved-voice cases
regress to English answers. Controls remain exact and truthful: all ten expected
commands are recorded only, with no real action. A language-tag probe fixes the
reply language but retains science errors, including a false seasons mechanism;
it was not promoted into the application.

| Measure, seconds | Previous baseline | 4B/new runtime |
| --- | ---: | ---: |
| FR history follow-up, accepted to WAV | 2.24 | 2.08 |
| EN history follow-up, accepted to WAV | 1.98 | 1.74 |
| Eight controls, median accepted to WAV | 0.71 | 0.73 |
| Four science turns, median accepted to WAV | 5.84 | 5.61 |
| EN saved voice, first PCM-end to WAV | 3.11 | 3.66 |
| EN saved voice, repeated PCM-end to WAV | 2.55 | 2.97 |
| Four queued replies, median accepted to WAV | 3.99 | 4.02 |

These small samples are descriptive, not statistical proof of equivalence. Audio
is captured on Apollo; no Mac speaker/microphone or physical playback was used.
A faster aggregate median cannot excuse the wrong-language replies or slower
English voice turns. The original 42 plus queue run audited 54 accepted requests,
54 terminal completions, four explicit overload rejections, and no external/DNS
attempts among 230 loopback destinations. Further science/tool probes are recorded
separately from that paired comparison.

The separate 24-case full-pipeline science run scores **20/24** (11/12 EN,
9/12 FR), compared with 13/24 (11/12 EN, 2/12 FR) for the old model. English
magnetism improves but photosynthesis loses essential inputs. French seasons
omits axial tilt, rain misdescribes condensation, and day/night merely restates
sunrise/sunset. Thus the higher aggregate score still includes a previously
correct case becoming incomplete. The private `science-manual-review.json`
records the per-case criteria/verdicts; no evaluation answers are used at runtime.

## Next engineering priorities

Keep the expanded factual and paraphrase suites as acceptance gates. Do not add
sentence-specific science answers or keep adjusting prompts against two examples.
The measurements support a model-quality limitation; a model swap has not yet
satisfied the full bilingual voice and latency constraints. Any further candidate
needs held-out transfer questions, voice-language checks, actual model tool calls,
and queue measurements before promotion.

For control breadth, follow the separate interaction-surface audit: correct the
French room-article defect, then compare bounded semantic interpretation on parser
misses, retaining server-owned inventory/capability validation and one-use action
grants. This is a recommendation, not implementation or acceptance of a final
control architecture. Wake-name activation and conversation expiry are likewise
missing features, not consequences of keeping message history.

## Actual model tool-loop checks and final audit

Four read-only inventory probes are separate from the ten deterministic control
commands. Both known-device probes call `find_devices` and include the expected
candidate, but take **17.39 s FR / 19.61 s EN** to first WAV. Two model calls spend
12.43/14.74 seconds generating 96/113 tokens in total. Replies list technical IDs
and command capabilities as if they were distinct devices; one French ID is
malformed. Both missing-device probes skip the requested lookup. English claims
absence without checking; French merely repeats the request. No action is granted
or executed. These probes establish candidate limitations, not a paired baseline
regression measurement or broad tool-call reliability.

A useful follow-up is compact, structured inventory results with server-rendered
spoken summaries, while retaining semantic interpretation and grounded execution
checks. Output rendering is different from hardcoding accepted input sentences;
it could remove the long second model turn without restricting synonyms. Measure
this separately before changing the control architecture.

After all full-pipeline suites, the audit finds **82 accepted / 82 completed**
requests, four explicit overload rejections, **zero physical actions**, and no
external/DNS attempts among 442 observed loopback destinations. Direct model
probes are additional requests outside the application admission counter. Source
hashes match the saved snapshot. No Mac audio was used. Peak RAM/CPU accounting
was unavailable from this host's systemd properties; watts were not measured.
Private results remain under run `20261018T075110Z-qwen4-runtime-ebf06d`, including
`science-comparison.json`, `science-manual-review.json`, `model-tools.json` and
`final-audit.json`.

Validation after cleanup of rejected source changes: **132 targeted Apollo tests**
passed (queue/shared processing, grounded control/local answers, prefill, warm-up,
logging/tools, speaker/language and harness audits), plus seven local context tests.
The context checker passes against HEAD and `git diff --check` is clean. The Mac
baseline-helper unit module was not rerun: Apollo lacks its client-only `soxr`
dependency and the Mac client environment lacks pytest. No client code changed in
this task; saved PCM replay was exercised through the real Apollo pipeline.
The isolated live, model-probe and preparation services were stopped after evidence
collection. Prepared candidate assets remain cached for future experiments; the
deployed runtime/model defaults were not replaced.
