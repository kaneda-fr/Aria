# Local entity matching options — 2026-10-18

Recommendation: normalize and resolve declared inventory aliases first, then bounded
spelling recovery and a small bilingual lexical layer. Evaluate phonetic matching
on remaining ASR failures. Embeddings are optional later; an additional generative
model call is the least preferred option, as explicitly requested by the maintainer.
This is an evaluation, not a new production matcher or an architecture decision.

## What Byname actually does

Inspected the separate local Byname checkout at `a72ff48`, without changing it.
Serena is scoped to Aria and rejected cross-workspace retrieval, so Byname source
was inspected directly. Relevant source paths within that repository:

- `packages/engine/src/m3/resolution/binder.ts:186`: mention normalization preserves
  recorded speech, folds case/Unicode, removes apostrophes, makes hyphens spaces,
  and removes a declared leading determiner.
- `packages/engine/src/m3/resolution/step-corrections.ts:23`: full Damerau distance
  counts adjacent transpositions as one edit. The automatic tier is unique distance
  one with no changed input token of three or fewer letters. Distance two, short
  tokens and competing candidates require a choice. Candidate nouns come from
  currently referable entity aliases; correction evidence is retained.
- `packages/engine/src/gen2/verb-lexicon/data.ts`: declared pack vocabulary (L1)
  precedes generated WordNet 3.1 vocabulary (L2). Head lemmatization and longest
  phrase candidates handle inflections/phrasal verbs. The generated lexical asset
  is local data, not embeddings or a generative model.
- `packages/engine/src/m3/resolution/gen2-step.ts:79`: an L3 classification can be
  consumed on a genuine L1/L2 miss. Byname as a whole is not model-free; the useful
  precedent here is its deterministic lexical/correction layer.
- `packages/engine/src/test/wo-play3-admission.test.ts`: behavioral examples cover
  exact/whole-word identity, ambiguity, short words, transpositions and correction
  choices. These tests were inspected, not rerun in this Aria task.

Older Byname rulings said no fuzzy matching; October 15 correction work superseded
that. Its English verb lexicon and game-specific binding rules cannot be copied as
a complete French/English household resolver. In Aria, two different devices must
remain distinct even when they expose identical actions.

## Aria's current gap

`InventoryProvider.get_candidates` delegates to strict `select_commands`; the older
`_score_candidate` heuristic remains in source but is not called by that entry point.
Current normalization folds accents/case and tokenizes punctuation. Thus the observed
split name containing an apostrophe becomes two tokens; Byname-style joining can
recover the original name. This happens before tool selection in the failed voice
case, so only changing the inventory provider would leave it unreached.

A read-only Apollo probe scanned all **69 enabled devices** using precomputed name
forms. On the saved failing transcript, current normalization found no exact name;
an apostrophe-joined comparison found exactly one, the intended device. Across 1,000
repetitions, normalization plus exact whole-name scan had median **0.0151 ms**, p95
**0.0154 ms**. Current normalization measured 0.0147/0.0178 ms. This microbenchmark
excludes index construction, candidate hints, model/TTS, queueing and phonetic work;
it proves neither general matching accuracy nor end-to-end latency improvement.
Private evidence: `name-normalization-probe.json` in the current run's report directory.
No runtime code or prompt was changed and no audio was generated by this probe.

## Comparison

| Method | Useful for | Cost and limitation | Recommendation |
| --- | --- | --- | --- |
| Exact normalization + declared aliases | Case, accents, punctuation, room abbreviations, known nicknames | No inference; aggressive joining/stripping can collide | First layer; retain alternative forms and entity IDs |
| Bounded Damerau/edit matching | Missing/swapped letters, small ASR spelling errors | Short names and similar devices collide; score is not probability | Second layer, close candidates retained; don't copy arbitrary thresholds as proof |
| Local lexical semantics | Synonyms and inflections, e.g. couch/sofa; declared FR/EN names for the same device type | Word senses and languages need explicit mapping; general relatedness does not establish identity | Compile constrained vocabulary against actual capabilities and aliases |
| Phonetic comparison | Sound-alike spellings and ASR word splits | Language/pronunciation-sensitive; homophones remain ambiguous | Optional corroborating signal, evaluated on saved speech |
| Multilingual embeddings | Broader paraphrases/descriptions and cross-language similarity | Query needs encoder inference even with cached device vectors; similar meaning can hide different rooms/opposite actions | Defer until cheaper layers' measured misses justify it |
| Extra generative reference model | Complex ambiguous interpretation | Additional model call, latency/RAM, invented candidates possible | Last resort; no added runtime model proposed |

Semantic comparison does not require a neural model: WordNet groups senses and
lexical relations in data. It is not a database of this house's names. Use only
relevant synonym senses; do not expand every related word, antonym or broad category.
An English derived vocabulary is insufficient for French: Open Multilingual Wordnet
includes WOLF, with different coverage/licensing and links based on WordNet 3.0.
Do not join Byname's 3.1 sense identifiers to that resource without an explicit mapping.

RapidFuzz offers edit distances and token/partial ratios. Avoid a token-set or partial
ratio as a final identity decision: a subset can score 100 despite extra words. Room,
side, number and exclusions must survive. eSpeak NG offers language-specific local
text-to-phoneme rules; this would compare pronunciations inferred from ASR text,
not recover original acoustic evidence. Cached name phonemes could bound repeated work.

## Proposed evaluation and integration

Build a bounded inventory-derived candidate helper before the existing model request
and reuse its representation in lookup. Keep raw input, span, candidate device IDs,
match method and competing alternatives. Exact match wins; room/capability can
disambiguate only when actually expressed or provided by an explicit session rule.
Do not rewrite the entire sentence, infer a command from a name mention, silently
drop negation/qualifiers, or let a recovery score authorize an action. Start by
passing concise lookup hints through the existing model call, not adding a new call.
Index refresh follows inventory changes; aliases are configuration/data, not canned
sentence handlers. Keep everything on Apollo; no ESP32 inference required.

Compare held-out FR/EN names and phrases across: exact names, apostrophe/word splits,
accent variants, transpositions, nickname/synonym aliases, similar-name pairs,
duplicate names across rooms, short names, unknown devices, multiple mentions,
negation/opposite actions and ordinary conversation about lights/furniture.
Measure candidate recall, wrong unique matches, clarification rate and unchanged
exact matches separately. Then run saved voice, exact tool-action, general-quality
and queue-inclusive latency checks; CPU/RAM and cold/warm index timings on Apollo.
Use separate tuning and held-out cases. Similarity scores are not calibrated
recognition probabilities. The observed apostrophe case alone cannot set thresholds.

Do not run audible benchmarks while the newly authorized Mac playback and ESP32
ingress are active. This review used read-only retrieval and CPU-only string work.
