# Wake-name conversation flow — 2026-10-18

[D-010](decisions.md) accepts name activation once, follow-ups without the name,
and closure on inactivity or goodbye. This change implements the session gate; it
does not add an acoustic wake model or claim reliable household name detection.

Follow-up: [spoken-name and self-rejection fixes](spoken-wake-2026-10-18.md)
supersede the exact-name-only voice behavior and unconditional nearest-self
suppression described in this initial report. Historical results below are retained.

## Behavior

- While waiting, only a leading `Aria` activates processing. Optional greetings are
  bonjour, salut, coucou, hello, hey, hi, hé, ok, and okay. Mentions in the middle,
  Maria, Ariana, and ordinary background requests do not activate it.
- A bare name gets `Oui ?` (default) or `Yes?` according to greeting/session language.
  A name plus request strips only the vocative before ordinary shared processing.
  Private logs and the HTTP response retain the original text.
- Follow-ups use the same WebSocket or explicit HTTP `session_id`; person attribution
  and confidence logs are unchanged. Speaker attribution is not an authorization
  boundary or proof that the same human continues speaking.
- The default idle window is 30 seconds, configurable from 1 to 600. It starts after
  server-estimated reply playback completes, with no additional wait in the worker.
  Voice uses server-observed speech onset, so ASR/queue delay does not expire a
  timely follow-up. Queue expiry still uses admission time, independently.
- Complete goodbye utterances close immediately. French: au revoir, à bientôt,
  à plus tard, bonne nuit, c'est tout, terminons la conversation. English: goodbye,
  good bye, bye, bye bye, see you, see you later, good night, that's all, end our
  conversation. Optional leading thanks/merci and trailing Aria are allowed.
  Bare thanks/merci or a question containing “goodbye” does not end a session.
- Closure, expiry, new activation, and capacity eviction reset history and grounded
  device references, and cancel matching speculative prefill. A new socket starts
  waiting. Up to 256 sessions are retained; expiry cleanup is lazy.
- No session ID means stateless HTTP: include the name every time. Disabled mode
  (`ARIA_WAKE_ENABLED=0`) exists for explicit legacy comparisons. Normal default is on.

The gate wraps the shared processor after bounded admission, before model/tools.
It adds no model inference, new dependency, timer loop, ESP32 requirement, or external
call. Ignored work has no speech or tool execution; its raw request is still logged.
ASR, speaker recognition, and echo filtering precede the gate and still consume CPU.
`SpeechOutput.playback_done` estimates completion using audio duration, not hardware
acknowledgment. Barge-in remains deferred. The existing reply/echo path is unchanged.

## Reproduction

Stage current `app` and `scripts/e2e` with the isolated live runner, cached models,
log-only actions, nearest-person attribution/confidence, history and tool warm-up.
Use the previous baseline Qwen2.5 3B model/prompt and Ollama 0.14.2, not the rejected
4B/model-runtime experiments. Keep Mac capture/playback off. The runner isolates
networking to loopback and captures WAV output; it cannot reach physical devices.

Prepare the independent input WAVs before testing, using locally available Piper
voices, and bind intended phrases to WAV hashes in `manifest.json`. The private
fixture directory on Apollo is `/data/aria/e2e/wake-fixtures`; it uses Ryan low and
UPMC medium, distinct from Aria's output voices. A second manifest in
`/data/aria/e2e/wake-fixtures-v2` uses Pierre and
[Lessac medium](https://huggingface.co/rhasspy/piper-voices/tree/main/en/en_US/lessac/medium);
use `--voice-only` to repeat the voice portion. No fixture downloads occur in the
operational request path. The benchmark sends 16 kHz mono PCM16LE over `/ws/asr`.

```sh
python -m scripts.e2e.wake_bench --server-run "$ARIA_E2E_RUN" \
  --fixtures /data/aria/e2e/wake-fixtures --output /private/report/wake.json
```

The report checks exact command IDs/values/payloads, history isolation/reset, actual
30-second expiry, and overlap/overload using the existing queue scenario. Original
ungated benchmarks must explicitly disable the gate for comparisons or activate each
session first; HTTP success with an ignored request is never a correct-answer pass.
